# AX.25 — the data link

AX.25 is the protocol that actually moves packets between stations on a radio channel. This
page explains what it does, how stations are addressed, the difference between connected and
connectionless working, and why its built-in digipeating does not scale — which is the
reason [NET/ROM](netrom.md) exists.

**AX.25 (Amateur X.25)** is a **data-link-layer** protocol — OSI layer 2 — derived from
layer 2 of the X.25 suite and adapted for amateur use. The long-standing baseline is v2.0
(Terry Fox, 1984); the authoritative specification is **TAPR's AX.25 v2.2 (1998)**, which
added efficiency improvements such as larger payloads, extended sequence numbers for bigger
windows, and Selective Reject. Adoption of v2.2 was slow — around 2020 Dire Wolf was noted
as the only known complete implementation.

## Frames

AX.25 borrows its frame structure from HDLC. There are three frame types:

- **I (Information) frames** carry user data, numbered, in *connected* mode.
- **S (Supervisory) frames** handle link control — Receive Ready, Receive Not Ready,
  Reject, and (in v2.2) Selective Reject.
- **U (Unnumbered) frames** set up and tear down connections, and include the
  connectionless **UI (Unnumbered Information)** frame.

## Addressing — callsign plus SSID

Each station in an AX.25 frame is identified by its **callsign plus a Secondary Station
Identifier (SSID)**. The SSID is a 4-bit number in the range **0–15**, so one operator can
run several distinct stations or services from one callsign — `CALL-1`, `CALL-7` and so on.
Two limits are worth knowing from the outset:

- AX.25 has a **hard six-character callsign limit**. The seven-character callsigns permitted
  since WRC-03 cannot be used on AX.25.
- AX.25 has **no separate port or service number**, so the SSID often doubles as a service
  selector — effectively one service per SSID. (XRouter's NetRom-X scheme is one way around
  that limitation; see [NET/ROM](netrom.md).)

## Connected mode vs UI frames

AX.25 supports two very different styles of working:

- **Connected (virtual-circuit) mode.** A link is established, data is acknowledged and
  retransmitted if lost, and frames are delivered in order. This is what you use for
  keyboard-to-keyboard chat, bulletin boards and connecting to a node.
- **Connectionless mode.** Single **UI frames** are broadcast with no connection, no
  acknowledgement and no retransmission. This is exactly how [APRS](aprs.md) works, and how
  nodes advertise themselves.

To share the channel, AX.25 uses **CSMA** (carrier-sense multiple access): stations listen
before transmitting to reduce collisions.

## Digipeating, and why it does not scale

A **digipeater** is a single-frequency store-and-forward repeater. When a station cannot
hear the one it wants to reach, it can list one or more digipeaters in the frame's repeater
path; each named digipeater that hears the frame retransmits it and marks itself as "done",
so the packet hops across the gap. This is simple **source routing** at layer 2 — the
sender spells out the path explicitly.

It works, but it does not scale to a real network:

- you must know and type the exact path for every connection;
- every hop competes for the same airtime, end to end;
- a single lost frame must be retried across the *whole* path.

Those weaknesses are precisely what [NET/ROM](netrom.md) and other layer-3 schemes were
created to solve, by adding automatic routing and per-hop acknowledgement on top of AX.25.
